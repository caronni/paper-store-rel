# Stage-2 reader diet for R2-FORMAT v1: the 2026-10-20 ladder (simulation only)

This is the typed stage-2 reader for the v1 page. It was dieted from the
readable reference `r2reader/reader.py` (431 counted lines). Every number
here is MEASURED in simulation on this machine. Nothing is printed, and
there is NO promotion: one render set.

**The delivered reader is `r2reader/reader_lite_v1.py`** (`v1/m14_panel21.py`).
It is rung d06 of the SET pass, hand-minified and identical in reads to d06
on all 63 set and margin cases. Typed total 3,895 (48 data lines; N2
30,240, B2 1983445071; the bundle is `r2reader/reader.py`).

d06 is d05 with the refuter's panel-21 fixes (the "Round 5" section):
unreadable input is reported and skipped, the progress line counts the
bullseyes, and a block on its seed's own row or column no longer takes
itself as its neighbour. d05 is d04 with the two format rulings of the
2026-10-20 night (the "Round 4" section): the block CRC covers the
payload's header, and the tail asserts the bundle's CRC-32 (B2). Round 4
delivered `v1/m12_bound.py` (d05), typed total 3,808. d04 is c29b with the last-page fix (set
I, end of the SET section). c29b read nothing on the mostly white last page
of a multi-page payload. Until round 4 the delivered reader was
`v1/m10_lastpage.py` (d04), typed total 3,784.

The first pass delivered r27 (typed total 4,336). That text is
`v1/m07_final.py`. The owner then ruled "Simplify the reader! We need good
enough recovery, not perfect." Acceptance became sets of frames that close
pooled, not single frames that close alone.

## Method

**Rungs.** `build_rungs_v1.py` builds every rung as its parent plus listed
text edits: each `old` occurs exactly once, or a region between two unique
lines is replaced. The files go to `v1/`.

- `r00` is `reader.py` itself, re-copied at every build.
- reader.py's reading code did not change until round 4 (rulings 20 and 22) and round 5 (the three fixes). Only its
  loader interface did, at 02:54: the shared block, its own `e = 'big'` and
  the b.py tail.

**The chain.** `w4_harness.py` runs each rung as the chain runs it:

- r.py = the loader's definitions (make_typed's typed program, line 2 up to
  its main part) + `make_typed.reader_text`, with N2 = 1, so the tail's
  decode is trivial.
- Frames are fed one per line and timed per frame, with at most 5 reader
  processes at a time.
- Rungs written against the v2 loader get `e='big'` prepended when run under
  the v3 definitions (`W4_COMPAT_E=1`). The delivered reader uses none of the loader's names (its own `e` is the header bytes).

**Sizes.** A rung's size is its typed reader text with comments and blank
lines stripped (the readable rungs carry prose the typed reader will not).
It is compressed with cm2 v2 (`typed/cm2_enc.py`, rANS, landed tonight),
with primer = `loader/a.py` of record (v3, 855 B).

- glyphs = the base-32 digits of x; data lines = ceil(glyphs / 60).
- `w4_ladder.py table` recomputes every row with the same coder and primer.

**Two envelopes.** The generator builder regenerated `build/w1` at 02:54:
designed placement, new payload, damage renders renamed and extended.

- **The first, 63 cases.** r00–r24, m03 and m05 ran on the 00:33 renders.
  Those files no longer exist; the results stay in
  `ladder-2026-10-20.json`.
- **The frozen copy, 71 cases.** The final comparisons (r00, r24, m05, m06,
  r27, m07) ran on a frozen copy of the 02:54 renders,
  `build/w4/w1frozen` (`W4_ENV=frozen`, results `env-F-*.json`).

## The owner's pose (clock lines) against the least-squares pose

### Seed accuracy (`w4_clockproto.py`; `build/w4/clockproto.txt`)

Setup:

- **Frames:** 24, from the first envelope: whole pages (σ 0.45, 1.5 spm,
  ±4°, turned), σ 0.45 quarters, middle thirds, close-ups and near frames.
- **Bullseyes:** 108, as found by the r08/r09 finder.
- **Comparison:** each pose's 17-module column and row vectors against the
  truth homography's local vectors at that bullseye, in the image-aligned
  convention.

| pose | worst angle | worst length | seeds beyond 1.5° or 3 % |
|---|---|---|---|
| clock lines as specified: row above / column left, 7-module windows, 2-D re-centring (r09) | 9.8° | 17.4 % | 84 / 108 |
| lateral-only re-centring at ±5 or ±6 modules, one or both sides | 13–14.5° | 4.5 % | 92–99 / 108 |
| following the lines outward, steps of 4 or 6 modules, 4 steps | 14.5–20.9° | 4.5 % | 79–99 / 108 |
| the bullseye block's timing frame (four clock lines, 68 modules), rotation only, per bullseye (r10) | 2.4° | 4.5 % | 41 / 108 |
| the same, A and B then from the four neighbours' refined centres | 4.0° | 6.1 % | 41 / 108 |
| the same, keeping the frame's best turn for the neighbours | 0.82° | 2.0 % | 0 / 108 |
| **JOINT** (r11 on): rotation and turn from ALL bullseye frames together, then A and B per seed from its neighbours | **0.82°** | **2.0 %** | **0 / 108** |
| least squares (r08: lattice snap, similarity / affine / homography, local-pitch points, tilt search alone) | 3.6° | 3.0 % | 8 / 108 |

The least squares pose's misses are the collinear middle thirds (a similarity
fit has no shear: B is off by 1.7–3.6°) and a turned quarter where only one
bullseye was found.

Why the clock lines as specified fail (`w4_profile.py`):

- **The clock line is the weakest signal near the bullseye.** A timing line
  alternates at one module. At σ 0.3–0.45 module that is attenuated to about
  ±35 grey levels at 2 spm. The header bits and data beside it keep their
  full contrast at lower frequencies.
- **Short windows lock onto the wrong rows.** An |alternating sum| over 7–9
  modules often scores a random row above the clock line, so re-centring
  locks onto the wrong row or slips one module along it.
- **A long window needs the angle first.** Beating random data needs roughly
  30 coherent modules, and holding a 30-module window on the line needs the
  angle in the first place.
- **The frame works because it is all four lines at once.** The bullseye
  block's four clock lines together (68 modules, signed alternation) are
  strong enough. Summing that score over all bullseyes of the frame removes
  the rare wrong maxima (on one.mid a wrong turn at −4.5° outscored the
  truth).
- **Each axis needs its own direction.** The camera's 2 % corner perspective
  gives local shear of up to 3.7° between the column and row directions,
  which a one-rotation pose cannot fit. A and B measured on the four
  neighbours' timing frames (the clock lines one block out, refined as the
  walk refines) give rotation, pitch and shear per seed. There is no least
  squares and no lattice snap.

### The walk that goes with the new pose

The least-squares design needed a global homography and up to three refit
walks; r06 shows them load-bearing.

The seed pose is local, so the walk carries its own lattice:

- **Index and placement.** Every block is (seed, i, j) in its seed's
  lattice. It is placed at its parent's refined centre plus the parent's
  17-module step, refined on its 68 timing modules (3 × 3 search, 1/2–1/16
  module).
- **Learned axes (r12).** Its A and B are then measured to its placed
  neighbours one block nearer the seed. Correcting only the axis it was
  reached along left the other stale: 0.35 module at block corners ten
  blocks from a lone seed.
- **Second read (r13, r27).** After the walk, every sound block whose CRC
  failed is read again, with A and B by central differences and its centre
  from the neighbours.
- **Deduplication.** All seeds walk in one breadth-first pass. A block
  within a 5-module cell of one already reached is skipped.

No lattice-vector snap is used anywhere.

### Orientation

The header's 20-bit check in the four quarter turns is the authority: per
seed, turn 0 relative to the frame's own turn is tried first.

The timing frame's 9/8 asymmetry is used for free: the joint frame score
maximises over the four turns. When no header checks, the reader uses that
turn instead of "upright" (spec question 3).

## Spec questions and weaknesses found

1. **All bullseyes blacked.**
   - Such a page gives nothing to any reader of this design. Decoding steps
     2–4 need a bullseye for the pose, and the header lives only in the
     bullseye blocks.
   - The spec's "assume the frame upright and still pool blocks" presupposes
     a pose.
   - The envelope's "bullseyes blacked … all" is unreachable by
     construction. Drop it, or accept that such a frame contributes nothing.
2. **Copy placement (resolved).** The first draft's copies sat in (band k,
   third (i + k) mod 3).
   - Every 3 × 3 arrangement puts one third of the chunks on the main
     diagonal or the anti-diagonal: the permutations split into the even set
     (with the identity) and the odd set (with the anti-diagonal).
   - A 5 mm diagonal scratch took one chunk whole, in two renders and at the
     true pose.
   - The 02:57 R2-FORMAT records the same finding and replaces the
     placement. The reader never reads the placement, so nothing changes
     here.
3. **Step 3, "assume the frame upright".**
   - The diet reader keeps the turn the timing frames give when no header
     checks. The 9/8 asymmetry is free from the joint frame score.
   - Upright would lose every block of a turned frame whose headers are
     damaged (r04: a turned near frame, 0 blocks).
   - Proposed: "the frame's own turn (the timing frames)".
4. **Step 4 describes the least-squares pose.** "One bullseye … rotation
   assumed 0; two or more … snapping … to the nearest lattice vector; four or
   more a homography."
   - The diet reader takes rotation and turn from all bullseye blocks' timing
     frames, and A and B per bullseye from its four neighbours' timing frames.
   - It never assumes rotation 0 and never snaps.
   - Proposed: "a reader poses each bullseye from the clock lines around it;
     one bullseye is enough".
5. **Step 5 describes block placement differently.** "each block's expected
   position comes from the pose and the neighbour's refined offset."
   - Here it comes from the neighbour's refined centre and learned 17-module
     step, with both axes re-measured block by block.
   - Sound-but-failed blocks are read a second time from their neighbours.
6. **Step 1, one global threshold.** "One global threshold is enough to find
   bullseyes" holds for reading. It does not hold for finding every
   bullseye: at σ 0.45, 3 spm, a turned quarter shows 1 of its 4.
7. **Camera shear.** Under the camera's 2 % perspective, local axis shear of
   up to 3.7° means a reader must allow non-orthogonal local axes. The
   corner displacements are independent per corner.
8. **The middle third alone is fragile.** Most of its chunks have only their

    loader version.
    - It is written for make_typed v3 / cm2 v2 as of tonight.

      `d(data,N2,open('r.py').read().encode())`.

    same length mix in one chunk pool: last write wins, and the header vote

### Proposed R2-FORMAT "Decoding" replacement (steps 1, 3, 4, 5, 6; step 2, 7 and the input note unchanged)

(Superseded. R2-FORMAT's Decoding section was rewritten to the typed
reader's steps from this and the refuter's panel 21; the round-4 amendments
to its steps 4, 6 and 7 are at the end of the "Round 4" section.)

These sentences describe what the delivered reader does; they replace the
current steps.

1. **Binarise the frame with one global threshold, midway between its
   darkest and its brightest sample.**
   - It serves only to find bullseyes.
   - It must not follow the paper. The last page of a payload is nine-tenths
     white, and a mean or a low percentile there sits next to the paper
     level and turns the blurred white rings to ink.
   - A bullseye a blurred or unevenly lit frame does not show is simply not a
     seed: the others, or the next frame, cover its part.
3. **Pose.**
   - The frame's rotation and quarter turn are those at which the timing
     frames around all its bullseye blocks agree best. Those are the four
     clock lines of each bullseye block, 68 alternating modules.
   - The search covers the four quarter turns and rotations in steps of
     about 1° up to ±9°.
   - The timing frame lies 9 modules out on the left and top of a centre and
     8 on the right and bottom, so the timing frames alone tell the turn.
   - Each bullseye becomes a seed: its centre, and the comb's pitch along
     both axes turned by that rotation. No bullseye is snapped to a lattice
     vector; no pose is fitted.
4. **Header.**
   - Read the 68 header bits around each seed, in the frame's turn, until
     one passes its 20-bit check. That header gives the length and the
     CRC-32 of the data, and confirms the turn.
   - If none passes, the reader keeps the frame's turn and still pools
     blocks. It cannot finish until some frame gives a header.
5. **Walk.**
   - Breadth first, from every seed at once.
   - A block is placed at a placed neighbour's centre plus that neighbour's
     17-module step. It is refined against its 68 timing modules: a 3 × 3
     search at ½, ¼, ⅛ and 1/16 module.
   - Its own two steps are then re-measured to its placed neighbours nearer
     the seed, so the walk follows perspective and shear.
   - The walk passes only through blocks whose timing modules alternate:
     their correlation with the timing pattern reaches 60 % of their
     contrast. A block whose lattice, one module beyond its timing lines,
     leaves the frame is not read and ends the walk there. A block whose
     predicted centre falls in a 5-module cell already
     reached is skipped; a duplicate that falls in another cell is simply
     read twice.
6. **Read.**
   - Each module is sampled at its centre and sharpened by half its
     Laplacian.
   - The block's threshold lies midway between the 9th darkest and the 9th
     brightest of its timing modules.
   - Accept a data block iff its CRC-32 matches, the plain read first, then
     each single-module flip.
   - Pool chunks by index across blocks, frames and pages.
   - A frame need not read every block. The payload is meant to close from a
     set of frames, and the finder photographs again where a frame falls
     short.

## Round 4: the header-bound block CRC and the B2 assert (2026-10-20 night)

Two format rulings changed the reader:

- **Ruling 20, the block CRC is bound to the header.** Bytes 28–31 of a data
  block are the CRC-32 over the six header bytes (length BE16, data CRC-32
  BE32) followed by the block's bytes 0–27. A block can be accepted only
  once a header is known; a frame with no header read and no earlier header
  accepts nothing (ruling 15: shoot again). Frames of another payload never
  validate.
- **Ruling 22, the tail asserts the bundle's CRC.** After the decode,
  `assert CRC(ou) == B2`, B2 being a second bare token that make_typed
  replaces with the bundle's CRC-32 in decimal, like N2.

**Frames.** The generator's fourth set, frozen into `build/w4/w1f4/` (the
grids of `one`, `two_p0`, `two_p1` are sha `0eb557c9…`, `b653e030…`,
`bd31f3fd…`, as build/w1). The extra set frames were re-rendered from it
into `build/w4/sets4/` with the same camera arguments. The last page was
regenerated with the current gen.py by `w4_lastpage.py` into
`build/w4/p2f4/` (the first 11,756 B of build/r2/payload.bin, 453 chunks;
page 3 holds 45 chunks and 435 white slots), with the ten frames rendered
from the camera parameters of the old page_p2 sidecars. d04 (the round-3
rung) reads 0 blocks on these frames: the format change is real.

**Which header.** The first header read in the session is the payload's.
Every later block is checked against it, and on the frame that gives it,
that frame's blocks too. A frame of another payload then accepts nothing.
The alternative, the newest header (what R2-FORMAT step 4 said before ruling 23 — the FIRST header now, and
what m10 did), lets a frame of another payload with a readable header
switch the session: its blocks validate against its own header and land in
the same chunk table. The first-header rule has its own cost: a false first
header (20-bit check, plain read; the refuter's 1.2e-4 expected false passes
over 131 failing reads) would stall the session until restarted. The
newest-header rule heals that at the next frame with a header. RULED
(coordinator, after this round): the first header stays — a frame of
another payload must add nothing, and a false first header is a restart,
which ruling 15 allows. m13b (below) was not taken: pooled, set I passes,
and the finder shoots again.

## Round 5: the refuter's panel-21 fixes (2026-10-20 night)

Ruled by the coordinator: the first header stays; m13b not taken; apply to
both readers the three fixes of `REVIEW-2026-10-20.md` panel 21:

1. **Unreadable input does not end the session** (a mistyped name, a
   trailing space from drag and drop, a directory, an empty file, a
   truncated or commented PGM, a 0 × 0 image, the end of input without an
   empty line). The name is stripped; any exception while loading or
   reading a frame gives one progress line with the note `cannot read`, and
   the next prompt follows; the end of input ends the run like an empty
   line.
2. **The progress line counts the bullseyes**, so the finder tells "none
   found: shoot closer or squarer" from "found, no header: shoot again".
3. **`if g and u:`**: a block on its seed's own row or column (u = 0) no
   longer takes its own earlier copy as the neighbour its step is measured
