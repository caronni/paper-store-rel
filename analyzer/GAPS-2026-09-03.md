# The C parity gap on sheet H — measured, 2026-09-03

Question: the H7 control re-derived only 11 of 16 production C certificates
with the default arm (`subtract+offset`, production context), where M was
20/20 and Y 17/20, and sheet I was 100/100.  Why?

Instruments (new, measurement only — no production-path behaviour changed):

* `analyzer/sweeps/c_parity_gap.py` — phases A (parity on a 60-tile
  band-stratified C sample), B/B2 (one-factor-at-a-time ablations over the
  missed keys).
* `analyzer/sweeps/c_ctx_scope.py` — phase D, the page-scope context fit
  against the per-footprint fit.
* Artefacts: `scratch/analyzer/sweeps/C-parity-gap/phase-{A,B,B2,D,E-full60}.json`.

One additive edit to the package: `arms.evidence_for` now reads
`knobs["branches"]`, defaulting to the unmix mode, so a measurement can ask
the same arm for the pooled PAVA map production actually fits.  Pinned by
`analyzer/tests/test_analyzer_gaps.py`.

## 1. The sample and the default rate

60 production-certified C tiles, hash-ordered inside each band
(2 dead — every dead-band C certificate on the sheet — 25 marginal,
33 live).  The 16-tile control sample is a subset by construction.

Default configuration: **49/60 = 81.7 %** (live 29/33 = 87.9 %,
marginal 20/25 = 80.0 %, dead 0/2).  Zero wrong certificates.

Re-run over the same 60 with the two configurations §4 nominates, so the
rate is a rate and not just a residue count:

| configuration | certified / 60 | live | marginal | dead |
|---|---|---|---|---|
| default (`subtract+offset`, sum, L0+L1) | 49 (81.7 %) | 29/33 | 20/25 | 0/2 |
| + pooled branches only | 52 (86.7 %) | 31/33 | 21/25 | 0/2 |
| halo 48 + pooled + all four rules | 56 (93.3 %) | 33/33 | 23/25 | 0/2 |
| whole 12-arm battery, all rules, full ladder | 56 (93.3 %) | 33/33 | 23/25 | 0/2 |

Pooling the branches costs nothing — zero regressions among the 49 the
default already had.  The last two rows leave the SAME four tiles
(`(0, 28, 5)`, `(0, 34, 31)`, `(0, 40, 31)`, `(0, 45, 4)`), so halo 48 +
pooled + four rules buys the whole battery's yield at a quarter of its cost
(33 s vs 136 s over the 60).

## 2. It is a waterfall, not a mode

Mean soft information rate R over the tile's seven lanes, against
certification, on the same 60 tiles:

| mean R      | certified / n |
|-------------|---------------|
| ≥ 0.95      | 32 / 32       |
| 0.90–0.95   | 10 / 13       |
| 0.85–0.90   | 4 / 6         |
| 0.80–0.85   | 3 / 7         |
| < 0.80      | 0 / 2         |

Hits average R = 0.994, misses 0.784 — but the distributions overlap from
0.825 to 0.933, and inside that band the outcome is a coin flip.  Ten of the
eleven missed tiles sit there; L0/L1 exit at 130–225 unsatisfied checks, not
at 1–10, so they are not near-misses that a stronger rung rescues.

## 3. The one structural bug: the branch split can erase the whole tile

`(0, 34, 34, C)` had **R = 0 and AUC = 0.5 on all seven lanes** with a
perfectly good score: the two-population split of DESIGN §4.7 put the
target tile's 3,976 payload cells into the `other` branch, which held
`n_fit_0 = 0, n_fit_1 = 0` labels and was refused `search_class_starved`.
The tile is erased, BP converges to the all-zero codeword in 0 iterations,
CRC fails.

The condition: every halo cell is sibling-proven (all eight neighbours
certified in all three planes) while the target's own siblings are not.
Page-wide on sheet H, page 0:

| target | tiles meeting the condition | production certified them |
|--------|-----------------------------|---------------------------|
| C      | 17 / 1961 (0.87 %)          | 17                        |
| M      | 18 / 1961 (0.92 %)          | 18                        |
| Y      | 7 / 1961 (0.36 %)           | 1 (6 are residue)         |

`branches="pooled"` recovers the tile outright (R 0 → 1.029, AUC 0.5 →
0.9957, certified).  So do `head+offset` and `conditional+offset`, whose
unmix modes are single-population.  Production never has this failure:
`plane_k.calibrated_rows` fits one PAVA map per window with no
cleanable/other split.

coarser lane, `(0, 34, 34)` +1.029 as the erased tile is un-erased).

## 5. Context scope: page-wide pooling is NOT the lever

One 9-bin fit per (lane, page) over 130 tiles' labelled cells,
leave-one-tile-out, evaluated on each tile's SELECT fold (903 lane×tile
rows; both fits adopt in 903/903):

| held-out select log loss | value |
|---|---|
| no context | 0.14107 |
| per-footprint fit (the analyzer's) | **0.08044** |
| page-scope pooled fit | 0.08171 |

The per-footprint fit is 1.6 % **better**.  The two differ materially per
cell — mean |ΔLLR| 0.251 nats over cargo (0.401 on the missed keys), 0.71 %
of cargo cells change sign (1.61 % on the missed keys) — and swapping in the
page-scope offsets certifies 3 of the 11 missed keys, byte-exact.  That is
the same yield as any comparable perturbation (halo 32 gives 3, halo 48
gives 4): a re-roll at the waterfall edge, not a better calibration.

Removing the context entirely is catastrophic (mean R −0.06 to −0.11 per
tile, cell error +2 to +4 pp, 0/11 recovered), which confirms the context
correction is already doing production's work.

## 6. What production did

`Certificate.source` over the 60: `retry150` 22/28 re-derived, `scan`
14/15, `union` 7/8, `local150` 6/6, `planek150` 0/1, `swim150` 0/2.  The
missed keys came from `retry150` (6), `swim150` (2), `scan`, `union`,
`planek150` (1 each) — no single production stage explains the gap.

Only 3 of the 11 have a `TileOutcome` in this run dir (the rest were minted
in the earlier resume-chain run whose events are elsewhere).  Those three
show how marginal they are: `(0, 45, 4)` took **362 recorded attempts**
across scan / retry150 / local150 / planek150 / swim150 / union before
retry150 minted it; `(0, 2, 29)` 189; `(0, 30, 29)` 54.

## 7. Diagnosis

Two causes, one of them small and structural, one of them the whole story.

The structural one is §3: the analyzer's per-footprint two-population PAVA
can leave the target tile in a branch with no labels and erase it — 17 C,
18 M and 7 Y tiles on this page, and 6 of the Y ones are residue the
instrument is supposed to attack.  That is a defect and it is cheap to fix
(fall back to the pooled map when a branch has no labels).

The dominant one is not a missing mechanism at all.  The C tiles production
had to work hardest for sit in the BP waterfall at mean R ≈ 0.80–0.93,
where certification is a coin flip; production won them by throwing six
tools and hundreds of attempts at each one, while the analyzer's parity
control fires a single arm, a single rule and two rungs once.  Every factor
that "recovers" a tile does so by moving R by one or two hundredths — a
different halo, a different unmix head, a coarser lane — and the full
battery gets 7 of 11 by having many such re-rolls.  The gap is therefore an
ATTEMPT-COUNT gap, not a capability gap, and the parity bar of 0.80 is
measuring how many re-rolls the default configuration gets rather than
whether the analyzer can read the C plane.  M is 20/20 because the M plane
is not in this regime on sheet H; sheet I was 100/100 for the same reason.

## 8. The structural fix, and DESIGN §4.7's amendment

**Amendment text, for DESIGN §4.7** (the sentence that changes is the one
ending "rather than pooling to reach them"):

> For `subtract`/`global` the score has two populations (cleanable vs not);
> ONE map per branch with its own standardisation, each refusing below
> `CAL_MIN_PER_CLASS`/`CAL_MIN_HELDOUT` rather than pooling to reach them.
> **A refused branch is not erased.  Its cells are priced by ONE map
> fitted over the footprint's union — the map `branches="pooled"` would
> have used — and the row records `branch_fallback` with that map's own
> class counts and acceptance.  Every branch that CAN fit keeps its own
> map and its own standardisation, so the fallback only ever replaces an
> LLR that would have been 0; when the union has no labels either, the
> fallback refuses too and the cells stay erased.**  The reason is
> measured: the two-population split can put the WHOLE target tile in a
> branch with no labels (halo fully sibling-proven, target's own siblings
> not), which erases a tile the score reads perfectly well — 17 C, 18 M
> and 7 Y tiles of sheet H page 0, every C and M one of them
> production-certified.  `labels_cleanable_fraction` and
> `cargo_cleanable_fraction` are recorded as before, and a gap > 0.2 is
> still flagged `extrapolating`.

`analyzer/calibrate.py`: `STARVED_FALLBACK` is now `True`;
`starved_fallback=False` still reaches the unamended behaviour, and the
pin that describes it (`test_analyzer_gaps.py::
test_the_branch_split_can_erase_the_whole_target_tile`) asks for it
explicitly.

## 10. The re-roll

`AnalyzerConfig.reroll` (default ON; `reroll_rungs` default `L0`, `L1`).
After the SELECTED arm's ladder fails for a key, `combine.reroll_sets`
hands back one evidence set per REMAINING arm — evidence the selection
already computed and threw away — and each set gets its own combination
per rule and its own L0/L1.  Every candidate is gated syndrome → CRC and
charged to the same exposure; the select fold is not consulted again, so
this is not a second arm choice, it is more rolls of the same dice, which
is what the §7 diagnosis says the C tiles are short of.  The winning arm
is recorded as `LedgerRow.certifying_arm` (`reroll:<arm>` for a re-roll,
the selected arm's name otherwise) and the rung rows are keyed
`<rule>|reroll:<arm>`, so the whole thing is auditable and every
certificate still passes through `score_rung`'s zero-wrong adjudication.

OFF for `controls.parity_sample` (RULED): a parity number measures what
ONE configuration re-derives, and spending the rest of the battery would
make the bar pass by changing the question.

**Measured, on the 8 keys the adopted defaults still miss in the C60
sample** (`reroll-H.json`; full 12-arm battery, all four rules, re-roll
against no re-roll, everything else identical):

| configuration | certified / 8 | seconds |
|---|---|---|
| battery, rungs L0+L1, no re-roll | 3 | 30 |
| battery, rungs L0+L1, **re-roll at L0+L1** (the default) | 3 (+0, −0) | 36 |
| battery, full ladder, no re-roll | 3 | 30 |
| battery, full ladder, **re-roll at L0+L1+L2** | **4 (+1, −0)** | 40 |

The certificate is `(0, 2, 29, C)`, minted by `reroll:conditional+offset` —
one of the tiles §6 records production taking 189 attempts to win.  So the
re-roll does pay, and it pays through the RUNGS: re-rolling the remaining
arms at L0/L1 alone recovered nothing on these keys, because L0/L1 on a
different arm is the same coin flip; adding L2 to the re-roll turned one
of them.  `reroll_rungs` is left at the specified `("L0", "L1")`;
**recommendation for the lead: `("L0", "L1", "L2")`**, which is what the
+1 was measured with, at +33 % wall time on this residue.

## 11. `local5`, the neighbourhood context (option, not default)

RULING 2026-09-03 (Germano): pose, page field and toner intensity are
LOCAL, so a fitted model takes a neighbourhood, not the sheet.  §5 above
measured the page-scope fit as 1.6 % WORSE than the per-footprint one, so
`ctx_mode="local5"` is for label-starved footprints and is not the
default.  `arms.local_context` fits the same 9-bin variable, the same
solver and the same `context_decision` gate over the 5×5 tiles centred on
the target (`arms.neighbourhood_tiles`, target excluded, page-clipped);
`calibrate._apply_local_context` then shrinks it toward the footprint's
OWN fit per bin,

    w_b = n_local_b / (n_local_b + n_footprint_b)

so a bin this footprint knows well keeps its own number and a bin it has
never seen takes the neighbourhood's — and adopts the blend only when it
beats the footprint's own correction on the footprint's own held-out
labels, under production's validation floors.  With no neighbourhood
context, or with one `context_decision` refused, the mode is
BYTE-IDENTICAL to `production`.
