## 043.0 The question

Design v0.3 §2.8 (R23) makes the M281's cmy route a device-RGB construct at
the engine's measured solid points — C (0,208,255), M (240,0,192), Y
(255,255,0), e041 S14–S17 — but every measurement of those points went through
8-bit Indexed DeviceRGB IMAGES inside PJL-wrapped jobs with HP's image
operators. One sheet, one plain PostScript job, asks:

1. **Mechanism.** Which lean constructs lay solid single toner unscreened:
   three colour imagemasks (`setrgbcolor` then `imagemask`, hex and ASCII85
   data), a 2-bit Indexed image, an 8-bit Indexed image without the HP calls —
   beside S16's construct as the measured control. No PJL anywhere.
2. **Colour points.** Both edges of each toner's solid plateau along each
   device axis at two-level steps; the midpoint of the non-screening range is
   the registry value (`devices/registry.py` `hp-m281`).
3. **Encoding.** Hex or ASCII85, 2 or 8 bits — the leanest job the engine
   prints identically.

Decisions of the day (owner, 2026-10-11): one `.ps`, no PJL, iterate only if
necessary; c2 bands only, no repeats; midpoint of the non-screening range with
the floor from the sheet's own controls (the MIC grid inside it); scan protocol
the owner's; no cmy format fragment on this sheet.

**The owner's question: what formula maps these RGBs to toner?** Not a formula and not published. HP's own material (developers.hp.com, "Color Concepts 101") describes ICC profiles per Color LaserJet and a formatter that converts to RGB and back to the engine's CMYK; HP's and others' patents (US5978011, EP1289268, US6833937) describe the color map as a multi-dimensional table of KCMY indexed by RGB, built per print mode, with black generation through 1-D LUTs on min(C, M, Y); support pages list sRGB IEC61966-2.1 as the emulation ("the average PC monitor"); the open-source colour lists note that untagged PostScript DeviceRGB is taken as sRGB by the RIP. What this sheet measured is consistent with exactly that: a 3-D table interpolated between nodes, whose node colours near each toner's sRGB appearance map to that toner alone (process cyan's canonical sRGB (0,174,239) has the G our plateau centres on; this engine's magenta node sits at a bluish (240,0,192–196)); between nodes the interpolation puts a few per cent of a neighbour toner into the output, which the screener renders as the sparse dots and stipples measured here, more in the active zones.
